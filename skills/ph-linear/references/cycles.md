# Cycles

- Cycles belong to a team. Resolve that team before reading or creating a sprint.
- Use explicit start/end dates and the requested timezone. Preserve unrelated cycle settings.
- Prefer archive for an ended cycle when removal is intended. Completion ratios reflect issue status, not effort estimates.

Cycle progress is a 0–1 ratio, not a percent. Keep the team's cycle boundaries
and timezone when converting ISO timestamps. Archiving a cycle preserves its
history; it is not equivalent to deleting its issues.
